# Frontend

React 19 + TypeScript on Vite, for the Incident Management System. See the
[root README](../README.md) for the full stack and [AGENTS.md](../AGENTS.md) for the rules that
apply to changes here.

## Run

```bash
npm ci          # installs exactly what package-lock.json says
npm run dev     # http://localhost:5173
```

`/api` is proxied to `http://localhost:8080`, so start the backend separately. There is no CORS
configuration to maintain.

In production, Vercel serves the app and `vercel.json` forwards `/api` to the Render backend, so the
code calls `/api` the same way everywhere. Every pull request gets a Vercel preview link.

Shared UI components (buttons, form fields, tables, badges) live in `src/components/ui/`. Pages use
them instead of styling their own.

## Scripts

| Command | Does |
| --- | --- |
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Typecheck and produce `dist/` |
| `npm run typecheck` | Types only, no output |
| `npm run lint` | oxlint |
| `npm test` | Vitest, once |
| `npm run test:watch` | Vitest, watching |
| `npm run test:coverage` | Vitest with v8 coverage |
| `npm run cypress:open` | Cypress, interactive |

Cypress needs both the dev server and the backend running.

## Layout

| Path | Contents |
| --- | --- |
| `src/main.tsx`, `src/router.tsx` | Providers and routes. Public: `/`, `/login`, `/status`. Everything else needs a login |
| `src/api/` | API client (adds the token, checks responses with Zod), schemas, auth calls |
| `src/auth/` | `AuthProvider`, the `RequireAuth` route guard, and role checks (`can(role, 'respond')`) |
| `src/components/ui/` | shadcn/ui primitives, generated by the CLI. Edit them only for a project-wide change |
| `src/components/effects/` | Animated components from React Bits, Aceternity UI, and Magic UI |
| `src/components/app/` | Settle pieces: severity, status, criticality, and role badges; clocks; uptime bars; loading and error states |
| `src/components/shell/` | The app shell: top bar, dock, ⌘K menu, theme toggle, wordmark |
| `src/components/theme/` | Light and dark theme (the `dark` class on `<html>`) |
| `src/pages/` | One file per screen; the landing page's sections are in `pages/landing/` |
| `src/data/` | Sample content for pages that have no API yet. Delete each file once its API exists |
| `src/index.css` | Tailwind, fonts, and the Settle design tokens |
| `cypress/` | Cypress setup; the end-to-end scenario arrives with #57 (Sprint 6) |

## Design

The look comes from the Settle design (Claude Design export). Colours, type, radii, and motion are
tokens in `src/index.css`, mapped to Tailwind classes such as `bg-sev-1-bg`, `text-status-open`,
`bg-deep`, and `shadow-elev-2`. Use these instead of raw colours, so light and dark both work.

- **Fonts:** Archivo (condensed headings use `font-stretch`) and JetBrains Mono for clocks,
  references, and timestamps. Both are self-hosted through Fontsource.
- **Icons:** `lucide-react`.
- **Motion:** use `motion/react` for movement that answers an action. Respect reduced motion
  (`useReducedMotion`).

## Adding components

```bash
npx shadcn@latest add dialog                                  # shadcn/ui primitive → components/ui
npx shadcn@latest add @react-bits/CountUp-TS-TW --path src/components/effects
npx shadcn@latest add @aceternity/<name>        --path src/components/effects
npx shadcn@latest add @magicui/<name>           --path src/components/effects
```

After adding:
- check the file's `cn` import points at `@/lib/utils`;
- check `package.json` gained only what the component needs.

## Forms

Use the shadcn `Form` components with react-hook-form and a Zod schema. In this project, each
input's `id` is its field name (`username`, `serviceId`, …), so labels, error messages, and
Cypress all find it. Server field errors (`ApiRequestError.errors`) go under the matching input;
`showRequestErrors` in `src/lib/forms.ts` does that, and puts any the form has no input for above
the buttons.

State that comes from the server belongs in TanStack Query, not in component state. Validate API
responses with Zod at the boundary. The backend re-checks every rule regardless, so validation here
is for the user's benefit, not for safety.
